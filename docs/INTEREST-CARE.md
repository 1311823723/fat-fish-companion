# 兴趣浏览与待续关心

## 已实现

- 复用 qq_browse：默认 action=read；plan 返回选题、候选内容与分享冷却；preferences 依据主人真实消息设置 topics/mutedTopics；feedback 依据真实反馈给最近实际分享的链接标记 like/dislike/neutral。
- 兴趣最多六个短公开关键词，必须原样出现在来源消息中，并有明确的正向表达。屏蔽需要明确负向表达，清空和解除屏蔽也需明确要求。关键词有网址、个人标识或指令等内容时拒绝，不把私聊原文当搜索词。
- 选题同时考虑主人兴趣和机器人本会话兴趣；候选按兴趣匹配及明确反馈排序，已分享、明确不想看的内容不再次推荐。网页内容仍为不可信外部资料。
- 分享先预留预算，OneBot 确认成功后才记录实际发送。只有实际发送的分享才接受反馈。明确的“这个我喜欢 / 这个我不喜欢”等表达可在最近六小时分享上下文中识别；普通回应只记为回应，不推断喜恶。
- 保留北京时间每天20页、仅主人私聊、分享至少间隔6小时、每24小时最多2条、链接去重。未获回应时至少间隔24小时，最近一周两次未回应则至少48小时；这不是负面兴趣标签。
- 有真实 sourceMessageId 的 pendingThought 可按 dueAt 获得独立 followUp 唤醒机会，不再仅依赖随机主动冒泡。来源、到期时间、机会次数保存在原有会话状态，重启恢复调度。夜间23:00—08:00推迟，过期/已关闭/两次机会后停止；两次机会至少相隔24小时。它是自然关心机会，不是精确闹钟，也不保证模型一定发言。
- 刷新、模式、暂停、白名单与 memory 工具开关继续生效。5秒健康检查会幂等恢复缺失的主动、独处和待续话题定时器。

## 使用示例

主人私聊：“我喜欢独立游戏和原神，可以偶尔给我分享这些。”

她可以依据这条真实消息，调用 qq_browse(action="preferences", topics=["独立游戏","原神"], sourceMessageId="真实消息ID")。

收到分享后：“这个我喜欢，以后多发这种。” / “这个我不喜欢，少发这种。”

取消某个话题：“我不想看原神的内容，屏蔽原神。”（mutedTopics）

待续话题通过现有 qq_memory_append(category="pendingThought", extra={sourceMessageId, nextCheckInMs, expiresAtMs}) 保存；已经解决用 qq_memory_remove 删除。不能凭空替用户安排事情。
