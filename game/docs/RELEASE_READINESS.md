# 首版部署验证与发布边界

发布定位：可自行部署的首版陪伴小游戏，持续维护。不要描述为平台官方产品或已通过多日稳定性验证。

## 已验证

- 从公开仓库全新克隆，在独立目录安装锁定依赖、生成默认配置、构建及导出发布包；不复制原机器的配置、账号、模型或 node_modules。
- Windows x64、Node.js 24 环境完成自动测试；完整仓库同时覆盖基础桥接暂存与访客隐私的集成测试。仅下载 game 导出包时，两项依赖旧桥接源码的集成测试会跳过，不能当成已经通过。
- 独立端口启动基础核心，诊断服务身份；基础玩法不要求 AI、QQ 或生图登录。
- 纯本地访客凭据仅保存哈希，数据库与对战记录在重启后保留；退出登录和过期凭据不能继续读取旧私有记录。
- 现有部署已验证手机与电脑访问、补货、家具交互、四子棋、历史棋谱、复盘找回及公开权限撤销。

## 部署顺序

1. 按 README 进入 game 子目录，先运行无 AI、QQ 的本地版本。
2. 检查版本与端口；确认房间、库存及四子棋能使用，再接外部服务。
3. QQ、文本模型、绘图各自依赖独立配置和登录。按 BRIDGE.md、AI.md 分步接入，不复制别人的凭据或主人身份。
4. 本机通过后再开公网；Cloudflare 提供静态网页和受限转发，本机后台和隧道仍需在线。
5. 修改前做一致性备份；外部登录或绘图额度问题应展示实际状态，不编造成功。

## 仍有的边界

- 本轮不宣称完成 72 小时连续运行验证；短时验收不等于长期稳定性保证。
- 未在 Linux、macOS、所有浏览器和所有网络环境逐一验收；先核对 Node 原生依赖与网络可达性。
- 生成式图片可能有服饰、动作等细节偏差，且上游网页接口可能改动、限额或要求本人验证。
- 不包含可直接复用的真人私聊、日记、QQ 登录、API 密钥或语音模型。
- 角色素材有独立署名及非商业授权，不能将代码的 MIT 许可解释为角色素材可商用。
