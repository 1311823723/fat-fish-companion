# 小屋加载性能记录

2026-11-12，本轮针对首次进入、衣柜打开和重复访问。

## 改动

- 首屏图片预算从2,682,656字节降为483,608字节，减少约82%。这是图片传输量，不包含JS、CSS和接口。
- 衣柜家具按实际显示大小生成192像素宽的透明WebP，从2,091,866字节降为8,434字节；源PNG保留。
- HTML优先加载并展示同一张房间底图，游戏就绪后淡出；加载进度来自实际图片加载事件，失败提供重试。
- 首屏仅加载基础站立；其他动作按需加载。取消进入后无条件下载经典服装摸头和转圈，不在静止时预下载两张走路图。
- 首屏稳定后以低优先级准备六张衣柜缩略图，遵守省流量/2G设置；不预下载整套服装。手机衣柜固定双列。
- 内容版本化的房间图片、JS、CSS长期缓存；HTML、状态、未版本化清单继续按原方式刷新。
- 环境只在天气、时段、家具、库存等视觉状态改变时重绘，普通状态轮询不再销毁重建食物对象和上传窗外纹理。
- 移除弹窗背景实时模糊；聊天气泡位置最多约30次/秒更新，坐标未变不重复写入样式。

`npm run build` 自动先运行 `scripts/prepare-room-assets.mjs`，生成 `public/assets/room-runtime.json` 及带内容哈希的图片。不要手工把旧图片内容覆盖到已有哈希文件名，也不要给未版本化的身份/状态接口设置长期缓存。

## 受控限速对比

本机两个独立HTTP测试入口，分别使用旧构建和新构建；每入口总带宽150 KiB/s、每次响应额外等待150ms、禁用HTTP缓存，文本使用gzip。相同浏览器、相同测试存档，页面可见；用测试入口的DOM观察器记录加载提示消失与canvas出现的时刻。测试工具不随公开版本发布。

## 验收

82项自动测试通过，包括素材预算、透明通道、缓存规则、身份边界、存档和已有玩法。独立小屋实测六张缩略图、睡眠中换装、窗帘、灯光、冰箱；浏览器桌面及375像素手机内容宽度通过检查，控制台无新增警告和错误。桌面观察约57fps，手机节能模式约30fps，只代表该测试设备当时场景，不是所有设备的保证。

保留旧素材和原服装编号，回滚可恢复上一版前端构建。公网仍取决于用户网络及本机后台链路；没有把静态优化当作后台迁移或完整美术重制。
