# 迁移、备份与回滚

迁移前先 `npm run migrate -- --source <旧项目>` 做只读检查。源存档仍会变化，正式迁移必须在停止旧桥接后重新读取，不能拿先前预览计数替代最终结果。

1. 确认桥接会话空闲，停止旧桥接；备份源码和 `state/room-web.json`，不要删除原文件。
2. 确认目标数据库不存在。运行 `npm run migrate -- --source <旧项目> --apply --db <新数据库>`。
3. 对照终端输出的食物、旅程、图片、身份、会话及补货计数。身份和私聊留在旧项目，不复制到公开文件。
4. 配置核心 `database` 指向新数据库，启动核心，再启用桥接适配。不要运行旧调度器或另一个游戏核心实例写同一存档。
5. 核对新页面、QQ 世界上下文、冰箱及旧照片。旧日记和聊天权限保持原系统。

运行中的一致性备份：`npm run backup`，使用 SQLite backup API，不直接复制正在写入的 `.db`。照片同时复制到本机 `state/backups/`。

回滚：停止新桥接与核心，禁用链接配置，恢复备份的桥接源码和房间存档，再启动旧版。新产生的事件保留在新数据库；切勿将两个版本的库存直接相加。回滚会停留在备份时的旧世界；需要保留新事件时应先导出核对再做人工合并。

恢复备份：停机后复制指定备份数据库和照片到新的目录，在 `config.local.json` 指向该数据库，先运行诊断再启动。不要在运行中的数据库上覆盖文件。

升级：备份 → 停机 → 更新程序 → `npm ci` → `npm test` → `npm run build` → `npm run doctor` → 启动。若 schema 不支持，保持停机，不自动重建旧存档。
